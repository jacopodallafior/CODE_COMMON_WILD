## High-Level Overview

### What is Jimny?

Jimny is **a fully autonomous vehicle control system** running on a Suzuki Jimny platform. The system can be operated in three modes:

- **MANUAL**: Driver uses HereLink remote controller to steer and accelerate/brake
- **ACRO**: Autonomous MPC (Model Predictive Control) follows a pre-loaded GPS waypoint path
- **LOITER**: Autonomous system identification mode with excitation signals (for research/tuning)

### How It Works (60-Second Version)

```
1. SENSING LAYER
   └─ CubePilot autopilot reads RC signals, GPS, and IMU
   └─ Sends all sensor data to Jetson Nano via MAVLink protocol

2. COMPUTATION LAYER (Jetson Nano)
   └─ State Estimator: Fuses GPS + IMU into vehicle state [position, velocity, heading]
   └─ MPC Controller: Solves optimization problem for optimal steering & velocity
   └─ Mode Logic: Selects between RC commands or MPC output based on operator choice

3. ACTUATION LAYER
   └─ Commands sent to three Arduino microcontrollers via serial/CAN:
      ├─ sterfBoard (master): Routes commands, handles emergency stop
      ├─ steerBok: PID steering angle control via stepper motor
      └─ axelBrake: PID velocity control via motor PWM + servo brake

4. FEEDBACK LOOP
   └─ Motor encoders + GPS send position/steering feedback back to Jetson
   └─ Closes the control loop for precise path-following
```

### Three Operational Modes

| Mode | Input | Use Case | Safety |
|------|-------|----------|--------|
| **MANUAL** | HereLink RC joystick | Driver-controlled testing, learning, fallback | Direct operator control |
| **ACRO** | Pre-loaded CSV waypoint file | Autonomous path-following, research | Vehicle must be stopped & centered before activation |
| **LOITER** | Excitation signals | System identification (parameter estimation) | Controlled signal injection |

## System Requirements

### Hardware Requirements

- **Jetson Nano** with Jetpack 6.0 installed
- **CubePilot** autopilot with MAVLink firmware
- **HereLink** RC remote control
- **Three Arduino microcontrollers** (or compatible):
  - sterfBoard (master controller)
  - steerBok (steering control)
  - axelBrake (drive/brake control)
- **Serial/UART connections** between Jetson and Arduinos
- **CAN bus** (500 kbps) for Arduino-to-Arduino communication
- **GPS receiver** (integrated in CubePilot or separate)
- **IMU** (9-axis: accelerometer + gyroscope + magnetometer)
- **Motor with feedback encoder** (steering)
- **Speed sensor** (GPS-based or wheel encoder)

### Software Requirements

- **Operating System**: Ubuntu 22.04 LTS (recommended for Jetson Nano)
- **ROS 2 Distribution**: Humble
- **Python Version**: Python 3.8+
- **Build System**: colcon
- **Python Package Manager**: pip

### Network & Connectivity

- SSH access to Jetson Nano (for development)
- Git access to repository (for code updates)
- Internet access for ROS dependency installation

## Build & Setup Instructions

### Step 1: Install ROS 2 Humble (If Not Already Installed)

```bash
# Add ROS 2 repository
sudo curl -sSL https://repo.ros2.org/ros.key -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://repo.ros2.org/ubuntu jammy main" | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

# Update and install
sudo apt update
sudo apt install -y ros-humble-desktop ros-humble-dev python3-pip

# Verify installation
source /opt/ros/humble/setup.bash
ros2 --version
```

### Step 2: Install System Dependencies

```bash
# Install colcon build tool
sudo apt install -y python3-colcon-common-extensions

# Install ROS-related development tools
sudo apt install -y build-essential cmake git python3-rosdep

# Initialize rosdep (only run this once)
sudo rosdep init
rosdep update
```

### Step 3: Clone & Prepare Repository

```bash

cd /path/to/jimnyws/jimny

# Export workspace path (add to ~/.bashrc for persistence)
```

## Launching the System

### Pre-Launch Checklist

Before launching, verify:

- [ ] Jetson Nano powered on and accessible via SSH
- [ ] CubePilot connected via USB (should appear as `/dev/ttyACM0`)
- [ ] Arduino boards flashed with latest firmware (sterfBoard, steerBok, axelBrake)
- [ ] Serial connections verified: `ls -la /dev/ttyACM*` and `ls -la /dev/ttyHS*`
- [ ] Workspace built successfully: `colcon build`
- [ ] ROS 2 Humble sourced: `source /opt/ros/humble/setup.bash`
- [ ] Workspace sourced: `source jimny_ws/install/setup.bash`
- [ ] Waypoint CSV file exists: `ls jimny_ws/src/mpc_driving_controller/data/waypoints/y_line_up.csv`
- [ ] Vehicle in safe location (flat surface, open area, no obstructions)
- [ ] E-stop button on sterfBoard accessible
- [ ] All safety measures in place

```bash
# Check CubePilot connection
ls -la /dev/ttyACM0
```

## Operating the Vehicle

### Step-by-Step Operating Procedure

#### Phase 1: Pre-Drive Safety Check (5 minutes)

```bash
# 1. Launch main system (see Launch 1 above)
ros2 launch to_vehicle do_jimny.launch.py

# 2. In a separate terminal, verify all topics are publishing
ros2 topic list | wc -l    # Should show 20+ topics

# 3. Check CubePilot heartbeat
ros2 topic echo /heartbeat

# Output should show:
# header:
#   seq: (increasing counter)
#   stamp:
#     sec: (current time)
# mode: "MANUAL"  or "ACRO"
# armed: true/false
```

#### Phase 2: Pre-Flight Checks (2 minutes)

```bash
# Terminal: Verify sensor data
ros2 topic hz /gps_raw       # Should be ~10 Hz
ros2 topic hz /imu_attitude  # Should be ~20 Hz
ros2 topic hz /rc_inputs     # Should be ~20 Hz

# Check state estimation running
ros2 topic hz /state_est     # Should be ~100 Hz

# Verify mode is MANUAL
ros2 topic echo /mode --once  # Output: "data: MANUAL"
```

#### Phase 3: Manual Mode Operation (Test RC Control)

**In MANUAL mode, the HereLink remote controls the vehicle directly.**

1. **Turn on HereLink Remote Control** (if not already on)
   - Press power button on HereLink transmitter
   - Green LED should illuminate
   - Check connection to CubePilot (should see telemetry on remote display)

2. **Ensure Vehicle is Disarmed** (critical safety step)
   ```bash
   # Check armed status
   ros2 topic echo /heartbeat | grep armed
   # Should output: armed: false
   ```

3. **Test RC Input Reception**
   ```bash
   # In a terminal, monitor RC channels
   ros2 topic echo /rc_inputs

   # On HereLink, move joystick:
   # - Move RIGHT stick UP/DOWN → Ch1 changes (steering)
   # - Move LEFT stick UP/DOWN → Ch4 changes (throttle)
   # - Values should swing from -1000 to +1000
   ```

4. **Verify Command Routing**
   ```bash
   # Monitor Ackermann commands being sent to vehicle
   ros2 topic echo /ackermann_cmd

   # Should see:
   # steering_angle: (varies with RC input)
   # speed: (varies with throttle)
   ```

5. **Test Motor Response**
   - Slowly move RC throttle from 50% to 100%
   - Observe steering motor responds to RC steering input
   - Listen for motor sounds (should be smooth, not jerky)

#### Phase 4: Switching to Autonomous (ACRO) Mode

**Prerequisites for safe ACRO activation:**
- Vehicle must be completely stopped: velocity < 0.1 m/s
- Steering must be centered: angle < 5 degrees
- Path waypoint file must be loaded
- MPC solver must report no errors

**Safety Procedure:**

```bash
# Terminal 1: Monitor vehicle state
ros2 topic echo /state_est | grep -E "v:|psi:|df:"
# Should show: v: 0.0, df: 0.0

# Terminal 2: Check mode before switching
ros2 topic echo /mode --once
# Output: "data: MANUAL"
```

**Switching to ACRO (on HereLink):**

1. Ensure vehicle velocity is 0 m/s (watch speedometer on HereLink display)
2. Ensure steering is centered (steering angle < 5°)
3. **Press AUTO button on HereLink** (or dedicated mode switch)
   - HereLink will send mode change command via MAVLink
   - sterfBoard will detect mode switch
   - System will transition to ACRO mode

**Verify Autonomous Activation:**

```bash
# In a terminal, check current mode
ros2 topic echo /mode

# Should change from:
# "data: MANUAL"
# to:
# "data: ACRO"

# Verify MPC is solving
ros2 topic hz /mpc_commands   # Should see ~5 Hz updates
ros2 topic echo /mpc_commands  # Should see non-zero steering/speed values
```

**Vehicle Behavior in ACRO Mode:**
- Vehicle will automatically start following waypoint path
- MPC solver computes optimal steering angle and velocity every 200 ms
- Steering motor responds to MPC commands
- Drive motor accelerates based on MPC velocity target
- **Feedback loop:** Encoder feedback → state estimation → MPC updates

#### Phase 5: Returning to Manual Mode

**To switch back to MANUAL mode:**

```bash
# Option 1: Press AUTO button again on HereLink (toggle)
# Option 2: Press Emergency Stop button (E-stop) on sterfBoard
# Option 3: Timeout (if no valid signal for >2 seconds)
```

**Verify Return to Manual:**

```bash
# Check mode changed back
ros2 topic echo /mode
# Output: "data: MANUAL"

# Verify E-stop (if pressed)
ros2 topic echo /signal_error
# Output: "error_code: 0" (disarmed)
```

#### Phase 6: Emergency Stop Procedure

**If anything goes wrong:**

1. **Press E-STOP button on sterfBoard immediately**
   - Kills power relay to all motors
   - All motors stop instantly
   - Servo brake engages

2. **Turn off HereLink remote** (secondary safety)

3. **Confirm safe state in terminal:**
   ```bash
   ros2 topic echo /heartbeat | grep armed
   # Should output: armed: false
   ```

4. **Shutdown ROS system:**
   ```bash
   # In terminal with ros2 launch, press Ctrl+C
   ```

## HereLink Remote Controller Setup

### HereLink Hardware Overview

```
HereLink Transmitter (RC Remote)
├── Power Button (top)
├── Mode Switch (MANUAL/AUTO/LOITER) - Right paddle
├── Emergency Stop Button - Left paddle  [typically hardwired on vehicle]
├── Left Joystick
│   ├── UP/DOWN (CH2) - Usually Throttle (not used on Jimny)
│   └── LEFT/RIGHT (CH3) - Usually Roll
├── Right Joystick
│   ├── UP/DOWN (CH4) - Velocity/Throttle ← **IMPORTANT**
│   └── LEFT/RIGHT (CH1) - Steering ← **IMPORTANT**
├── Trimmer knobs
├── Screen (shows telemetry: speed, heading, altitude, signal strength)
├── LED indicator (green = armed, red = disarmed)
└── USB port (for firmware updates)
```

### Channel Mapping on Jimny

The HereLink sends **4 main RC channels** to CubePilot:

| Channel | Stick | Range | Mapping | Jimny Function |
|---------|-------|-------|---------|---|
| CH1 | Right LEFT/RIGHT | -1000 to +1000 | Steering Input | Steering Angle (-30° to +30°) |
| CH2 | Left UP/DOWN | -1000 to +1000 | (Not used) | - |
| CH3 | Left LEFT/RIGHT | -1000 to +1000 | (Not used) | - |
| CH4 | Right UP/DOWN | -1000 to +1000 | Velocity Input | Speed (-10 to +10 km/h) |

**Channel Scaling (mode_switch.py):**
```python
# Steering: CH1 [-1000, 1000] → [-30°, 30°]
steering_angle = (ch1_raw / 1000.0) * 30.0  # degrees

# Velocity: CH4 [-1000, 1000] → [-10, 10] km/h
velocity = (ch4_raw / 1000.0) * 10.0        # km/h → m/s conversion: * 0.277
```

### HereLink Physical Operation Steps

#### Starting the Mission (First Time)

1. **Power on HereLink**
   - Press power button on top (left side)
   - LED changes from off → red (disarmed)
   - Wait 3 seconds for radio initialization

2. **Connect to CubePilot**
   - HereLink automatically searches for CubePilot
   - On CubePilot, press Arm button (or via terminal)
   - LED changes to green (armed)
   - Screen shows: "ARMED, Ready to fly"

3. **Verify Telemetry Link**
   - HereLink screen should show:
     - GPS: Green checkmark (3D fix acquired)
     - Signal: 4 bars (strong signal)
     - Speed: 0.0 m/s (vehicle stopped)
     - Heading: (current compass bearing, e.g., 180°)

#### Operating Instructions (During Test)

**For MANUAL mode (RC joystick control):**

1. **Steering (Right Joystick, LEFT/RIGHT)**
   - Move joystick **LEFT** → Vehicle steers left (-30°)
   - Move joystick **NEUTRAL** → Vehicle goes straight (0°)
   - Move joystick **RIGHT** → Vehicle steers right (+30°)
   - Movement should be smooth and proportional
   - **Tip:** Hold at neutral → vehicle stays centered

2. **Velocity/Acceleration (Right Joystick, UP/DOWN)**
   - Move **DOWN** → Brake / Reverse (-10 km/h)
   - Move **NEUTRAL** → Stop (0 m/s)
   - Move **UP** → Accelerate (+10 km/h)
   - Response is smooth, not jerky
   - **Always return to neutral after test**

3. **Speed Monitoring**
   - Watch speedometer on HereLink screen (top right)
   - Shows GPS-based velocity in real-time
   - Helps verify which direction vehicle is moving

**For AUTONOMOUS mode (AUTO / ACRO):**

1. **Ensure Vehicle Stopped**
   - Bring vehicle to complete stop (velocity = 0)
   - Center steering (joystick at neutral)
   - Hold stable for 2 seconds

2. **Press Auto Button (Mode Switch)**
   - Look at HereLink control scheme (custom setup)
   - Usually a **spring-loaded switch** or **mode button** labeled "AUTO"
   - **Safety:** Most HereLink setups require **spring-return to MANUAL** for safety
   - Once pressed: LED flashes (mode change in progress) → stays green (armed in AUTO mode)

3. **Vehicle Starts Moving Autonomously**
   - Steering motor begins PID tracking commands from MPC
   - Vehicle smoothly accelerates/decelerates following waypoint path
   - **Do NOT move joystick** while in AUTO mode (control locked)
   - HereLink screen shows real-time speed, heading, position

4. **Monitor Autonomous Operation**
   - Watch HereLink screen GPS track (shows vehicle path in real-time)
   - Speed varies as MPC adjusts for turns and waypoint changes
   - Release RC sticks completely (neutral)
   - If erratic behavior: **Press E-stop immediately**

**Returning to MANUAL:**
- Press AUTO button again (toggle back)
- LED flashes (mode change) → goes green again
- Control returns to RC joystick
- **Always verify mode change before operating**

## Mode Switching: Manual vs Autonomous

### Understanding the Three Modes

#### Mode 1: MANUAL (RC Joystick Control)

**Activation**: Default mode when system starts
**Control Source**: HereLink remote joystick input
**Safety**: Full operator control, instant response

```
HereLink Joystick
    ↓
RC channels (CH1, CH4)
    ↓
mode_switch node
    ↓
Passes RC input → /ackermann_cmd
    ↓
to_vehicle serializes command → Arduino → Motors
```

**Motion Feel**: Direct, proportional response to stick input
**Stopping**: Release throttle joystick to neutral → vehicle coasts/brakes
**Steering Response**: Immediate (no MPC computation delay)

**When to Use MANUAL Mode:**
- Testing motor hardware
- Learning vehicle behavior
- Safe fallback mode
- Slow-speed maneuvering
- Obstacle avoidance (immediate RC response)

#### Mode 2: ACRO (Autonomous MPC Path Following)

**Activation**: Press AUTO on HereLink when vehicle is stopped and centered
**Control Source**: Pre-loaded GPS waypoint CSV file + MPC solver
**Safety**: Vehicle must meet activation guards before ACRO engages

```
Waypoint CSV file (y_line_up.csv)
    ↓
waypoint_generator_node: Request 20-waypoint horizon
    ↓
controller_node: Solves MPC optimization problem
    ↓
MPC Output: Optimal steering angle + velocity
    ↓
mode_switch selects MPC input (not RC)
    ↓
/ackermann_cmd sent to vehicle
    ↓
Autonomous path-following
```

**Activation Guards** (preventing unintended ACRO startup):

```python
# From mode_switch.py:
can_activate_autonomous = (
    velocity < 0.1 m/s AND              # Vehicle must be stopped
    steering_angle < 5 degrees AND      # Steering must be centered
    heartbeat_valid AND                 # CubePilot communicating
    mpc_not_errored                     # Solver converged
)

if can_activate_autonomous and user_pressed_auto_button:
    activate_ACRO_mode()
```

**Motion Feel**: Smooth, planned motion following curved path
**Stopping**: MPC decelerates autonomously as waypoints end
**Steering Response**: Slightly delayed (5 Hz MPC computation → 200 ms cycle time)

**When to Use ACRO Mode:**
- Repeatable autonomous missions
- Path following with precision
- Research & testing trajectory tracking
- Data collection on known paths

#### Mode 3: LOITER (Excitation for Identification)

**Activation**: Via parameter change (rarely used in field)
**Control Source**: Predefined excitation signals (square wave, chirp, etc.)
**Purpose**: System identification for parameter estimation

```
Excitation signal generator
    ↓
/excitation_cmd (square wave or chirp on steering + velocity)
    ↓
mode_switch selects excitation input (not RC or MPC)
    ↓
Vehicle performs identification maneuvers autonomously
```

**When to Use LOITER Mode:**
- Estimating vehicle model parameters (mass, friction, etc.)
- Validating controller tuning
- Research only (not for normal operation)

### Mode Switching State Machine

```
                            ┌─ STARTUP ─┐
                            │   Check    │
                            │ Heartbeat  │
                            └─────┬──────┘
                                  │
                    ┌─────────────┼─────────────┐
                    │             │             │
                    v             v             v
            ┌──────────────┐  ┌──────────┐  ┌────────────┐
            │   DISARMED   │  │  MANUAL  │  │   ERROR    │
            │   No Signal  │  │   (Armed)│  │  (Invalid  │
            │   Fallback   │  │   RC ON  │  │   Signal)  │
            └──────┬───────┘  └────┬─────┘  └──────┬─────┘
                   │              │               │
                   │ heartbeat OK  │               │ heartbeat back
                   │              │               │
                   └──────────────┴───────────────┘
                                  │
                    ┌─────────────┴─────────────┐
                    │                           │
                    v                           v
            ┌──────────────┐           ┌──────────────┐
            │   MANUAL     │           │   ACRO       │
            │ (RC Control) │──────────▶│ (Autonomous) │
            │              │ Auto btn  │              │
            │              │◀──────────│              │
            └──────────────┘ Auto btn  └──────────────┘

            E-stop OR timeouts → DISARMED (fail-safe)
```

### Switching Between Modes (Step-by-Step)

#### Manual → Autonomous (RC to ACRO)

```bash
# Step 1: Terminal - Monitor current mode
ros2 topic echo /mode --once
# Output: "data: MANUAL"

# Step 2: Bring vehicle to complete stop
# - HereLink throttle joystick → NEUTRAL
# - Wait 2 seconds for velocity filter to settle
# - Verify on HereLink screen: Speed = 0.0 m/s

# Step 3: Center steering
# - HereLink steering joystick → CENTER
# - Verify steering angle visually on vehicle (~0°)

# Step 4: Press AUTO button on HereLink
# - LED flashes (2-3 times) during mode change
# - After 2 seconds: LED solid green = ACRO mode active

# Step 5: Verify mode changed
ros2 topic echo /mode --once
# Output: "data: ACRO"
# Vehicle should start moving autonomously

# Step 6: Monitor autonomous operation
ros2 topic hz /mpc_commands   # Should see 5 Hz updates
ros2 topic echo /ackermann_cmd  # Should show MPC steering/velocity
```

#### Autonomous → Manual (ACRO to RC)

```bash
# Step 1: Terminal - Confirm ACRO mode
ros2 topic echo /mode --once
# Output: "data: ACRO"

# Step 2: Press AUTO button again on HereLink
# - LED flashes during mode change
# - Control returns to RC joystick

# Step 3: Verify mode changed back
ros2 topic echo /mode --once
# Output: "data: MANUAL"

# Step 4: Resume RC control
# - Move HereLink joystick to test steering/throttle
# - Vehicle should respond immediately to RC input
```

#### Emergency Stop (Any Mode → Disarmed)

```bash
# Step 1: Press E-STOP button on sterfBoard
# - All power relays disabled immediately
# - Motors stop (stepper disabled, servo brake engaged)
# - Vehicle coast to halt

# Step 2: Verify disarmed state
ros2 topic echo /heartbeat | grep armed
# Output: armed: false

# Step 3: Check error state
ros2 topic echo /signal_error
# Output: error_code: 0  (DISARMED)

# Step 4: System is now safe to approach
# Manual inspection of vehicle, troubleshooting, etc.
```

### Mode Switching Troubleshooting

| Problem | Cause | Solution |
|---------|-------|----------|
| Vehicle won't switch to ACRO | Velocity > 0.1 m/s | Bring vehicle to complete stop (wait 2-3 sec) |
| Vehicle won't switch to ACRO | Steering > 5° | Center steering joystick, wait for servo to catch up |
| Vehicle won't switch to ACRO | MPC error | Check MPC solver status: `ros2 topic echo /mpc_error_state` |
| Vehicle switches then immediately back to MANUAL | Heartbeat timeout | Check CubePilot connection `/dev/ttyACM0` |
| RC control unresponsive in MANUAL | HereLink not communicating | Check HereLink battery, signal bars on screen, re-arm |
| Autonomous steering jerky | MPC frequency too high | Reduce from 5 Hz to 2 Hz in launch file |
| Vehicle overshoots waypoints | Velocity too high | Lower reference_velocity in launch file (default 2.0 m/s) |


**Problem**: `CubePilot not responding` / MAVLink connection fails

```bash
# Verify CubePilot is connected
lsusb | grep "Hex"
# Should show: Bus XXX Device YYY: ID XXX:XXXX Hex Innovations...

# Check if device shows up
ls -la /dev/ttyACM0

# Try manual serial connection (115200 baud)
sudo apt install minicom
minicom -D /dev/ttyACM0 -b 115200

# If working, should see MAVLink heartbeat messages
```

**Problem**: MPC solver times out (taking > 200ms)

```bash
# Solution 1: Reduce prediction horizon
# In controller.launch.py:
N: 15        # Instead of 20

# Solution 2: Reduce MPC frequency
# In controller.launch.py:
f: 2.0       # Hz (instead of 5.0)

# Solution 3: Use Cartesian MPC (faster)
# In controller.launch.py:
USE_FRENET_MPC: False   # Uses Cartesian coordinates instead
```

#### Data & Trajectory Issues

**Problem**: "Waypoint file not found"

```bash
# Verify waypoint CSV file path
ls jimny_ws/src/mpc_driving_controller/data/waypoints/y_line_up.csv

# If missing, list available waypoints
ls jimny_ws/src/mpc_driving_controller/data/waypoints/

# Edit launch file to use correct waypoint file:
# In controller.launch.py change:
waypoint_file: 'y_line_up.csv'  → 'circular_path.csv'  # or other available file
```

**Problem**: Vehicle drives off path (waypoint following is inaccurate)

```bash
# Check 1: Verify state estimation accuracy
ros2 topic echo /state_est
# Should show smooth x, y, v values (no jumping)

# Check 2: Verify GPS accuracy
ros2 topic echo /gps_raw | grep accuracy
# hdop should be < 2.0 (lower = better)

# Check 3: Tune MPC cost weights in controller.launch.py
Q: [1.0, 1.0, 10.0, 0]  → Try [2.0, 2.0, 20.0, 0]  # Increase position tracking cost

# Check 4: Reduce speed to improve accuracy
reference_velocity: 2.0  → 1.0  # Slower = more accurate

# Check 5: Increase prediction horizon
N: 20  → 30  # Longer lookahead (if processing allows)
```

#### Hardware Control Issues

**Problem**: Steering motor not responding (stops immediately)

```bash
# Check 1: Verify Arduino is receiving CAN messages
# On sterfBoard, check heartbeat LED (should blink every 200ms)

# Check 2: Monitor CAN bus traffic (if hardware available)
candump can0

# Check 3: Verify steering command is being sent
ros2 topic echo /ackermann_cmd
# steering_angle should change when moving joystick

# Check 4: Check Arduino firmware on steerBok

```

**Problem**: Velocity control too aggressive (jerky acceleration)

```bash
# Solution: Tune axelBrake PID parameters (in axelBrake.ino)
P = 0.5   → 0.2  # Reduce proportional gain
I = 1e-4  → 5e-5 # Reduce integral gain
D = 1e-2  → 5e-3 # Reduce derivative gain

# Recompile and flash Arduino firmware
```

## Tips for Development

### Code Organization Best Practices

#### Python ROS Nodes

All ROS 2 Python nodes follow this template:

```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node

class MyNode(Node):
    def __init__(self):
        super().__init__('my_node')

        # Declare parameters
        self.declare_parameter('param_name', default_value)

        # Create subscriptions
        self.subscription = self.create_subscription(
            msg_type, '/topic_name', self.callback, queue_size=10)

        # Create publishers
        self.publisher = self.create_publisher(
            msg_type, '/output_topic', queue_size=10)

        # Create timers for periodic tasks
        self.timer = self.create_timer(0.2, self.timer_callback)  # 5 Hz

    def callback(self, msg):
        # Process incoming message
        pass

    def timer_callback(self):
        # Periodic computation
        pass

def main(args=None):
    rclpy.init(args=args)
    node = MyNode()
    rclpy.spin(node)
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

#### Adding a New ROS Node

1. **Create new file** in `src/[package]/[package]/new_node.py`
2. **Add entry point** in `src/[package]/setup.py`:
   ```python
   entry_points={
       'console_scripts': [
           'new_node = [package].new_node:main',
       ],
   },
   ```
3. **Rebuild workspace**:
   ```bash
   cd jimny_ws
   colcon build --packages-select [package]
   ```
4. **Test the node**:
   ```bash
   ros2 run [package] new_node
   ```

### Parameter Tuning Workflow

Standard process for tuning controller parameters:

1. **Identify Issue**: Vehicle overshoots → MPC cost weight too low
2. **Change Parameter**: Edit `controller.launch.py`
   ```python
   Q: [1.0, 1.0, 10.0, 0]  →  [2.0, 2.0, 20.0, 0]
   ```
3. **Rebuild** (if C++ code) or restart nodes:
   ```bash
   ros2 launch to_vehicle do_jimny.launch.py
   ```
4. **Test**: Run vehicle through same course
5. **Evaluate**: Compare trajectory, overshoot, settling time
6. **Iterate**: Adjust further or accept tuning
